## 接手顺序

1. 用桌面 v30 看网桥预览，点击「开始遥控」，回中后用原装解锁键。停遥控、关预览、切换链路或画面中断都会停发。先架空，用真实车轮和舵机判断方向及停转。
2. 若云端仍是 v1，在阿里云 Workbench 上传 `YRT-Remote-Control-Gateway-v2.tar.gz` 到 `/root/`，执行下方命令。安装器在现有服务上打补丁，检查接口的认证响应，失败会回滚。域名仍是 `https://yuyunchang.cn/yrt-mobile/`。
3. 开 4G 图传和中位控制同时复测。采集持续有效时间、最大失联空档、恢复后是否要求重新解锁。车端 HTTPS 绑定 4G 网口，挑战年龄超过 450 ms 的帧作废。网桥最大年龄 200 ms。分别验收真实掉线和重新接入；旧样本或视频卡顿不能继续驱动车轮。
4. 如果 4G 仍会频繁回中，从网关收到挑战、电脑提交、车端接收三处加时间记录。车端到网关实测往返约 185–200 ms，首次握手可达约 408 ms。当前车端使用三个错开连接，v2 网关当前请求等待新数据最多 120 ms。先定位长尾和拥塞，再决定后续传输改法。

```bash
stage=$(mktemp -d) && tar -xzf /root/YRT-Remote-Control-Gateway-v2.tar.gz -C "$stage" && python3 "$stage/deploy/mobile-gateway/install-control.py"
```

成功输出 `4G remote-control API active`。纯探测 `POST /yrt-mobile/api/v1/remote-control/pc` 不带令牌应返回 401；这个结果只能证明路由及鉴权存在，无法区分 v1/v2 或证明遥控稳定。

## 车端与复现

- 板端 SSH：`ztl@192.168.137.246`，Windows 网桥地址 `192.168.137.10`。检查 `systemctl is-active yrt-remote-control yrt-camera yrt-fusion-rx` 和 `journalctl -u yrt-remote-control -n 30 --no-pager`。正式遥控文件装在 `/opt/yrt-remote-control/`，网桥 SSH 转发对接 `/run/yrt-remote-control/operator.sock`。
- OTG 控制器 `fc000000.usb`。测试时发现不切角色就同时为 Host，不能直接接两端。**重启 3588 前先拔掉底盘 USB。** 启动后通过已授权的 sudo 将 `peripheral` 写入 `/sys/devices/platform/fd5d0000.syscon/fd5d0000.syscon:usb2-phy@0/otg_mode`。检查 `/sys/class/extcon/extcon0/state` 中 `USB_VBUS_EN=0` 和 `/sys/class/udc/fc000000.usb` 存在后再接回。服务目前是手动启动，未设为开机自启。板端包解开后用 `sudo sh deploy/three-link/install-control.sh` 安装或恢复。
- Astra Pro 已换到固定 Host。最后一次读取暂未看到 LoRa 的 CH340；本次遥控只接入网桥和 4G。LoRa 的串口和原三链路实验独立确认。
- Windows OpenSSH 指定 `-b 192.168.137.10` 会报参数无效，v30 移除了该选项。Windows 路由已确认目标走以太网。XInput 和 USB 台架脚本仍保留，用于离线定位。
- 原装接收器报 `045e:028e`，制造商 `Flydigi`。原厂接口的专有 0x21 描述符不被现有 FunctionFS 接受。最初用缺少 HID 报告描述符的兼容方案时，只枚举，底盘没有开始读。改为合法 HID 描述符、答复 GET_REPORT/SET_IDLE/SET_PROTOCOL，并把 USB 控制请求和中断报告各自处理后，底盘开始连续读报告。OLED `PS2 ON` 是进入手柄模式且底盘允许动力的现场佐证。
- 重复停止临时 USB 测试时曾遇到 Linux `umount` 卡在 RCU，同时 SSH 登录卡住。先断开底盘 USB 并重启 3588 后恢复，正式版使用独立的长驻服务，应用启停不反复挂卸 FunctionFS。若再次遇到这类卡死，先查 `ps`/内核日志，按同样的顺序断开并重启。
- 延续旧配置里的 HTTPS 令牌和 SSH 配置即可。**令牌、密码、密钥和现场用户配置未入库。** 板端 LTE 配置仍在 `/etc/yrt-mobile-gateway/vehicle.json`，Windows 项目运行配置仍在 `D:/YRT/three-link/windows.json`。
