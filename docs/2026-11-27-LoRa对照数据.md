# 2026-11-27 LoRa 延迟对照数据

两块 CH340 各自做串口回环时，20 字节完整帧的中位数约 **23 ms**。接回这对 HD-M805 后，同条件的无线对照中位数为 **141–188 ms**，接收首字节还呈现约 **100 ms 的节拍**。一次近距离连续采样的重插试验把排查重点收窄到了接收端。下文保留具体条件、失败记录和判断的边界。

## 测量口径

- 两只转接板接到同一台 Windows 电脑，使用同一个单调时钟。无线轮次的链路为电脑 UART 写入、发射模块、空中链路、接收模块、电脑读取。测试链路不经过 RK3588、Wi-Fi 网桥或 4G。
- UART 使用 **9600、8N1**。帧有序号和 CRC，收到完整且通过校验后计入接收。完整帧延迟从调用串口写入前计到应用读齐整帧，包含串口、USB 和应用读取开销。它衡量这条链路上应用实际看到的单程延迟。
- 除注明的 1 Hz 预检外，下表轮次以 2 Hz 发包。随后随机化发包间隔，避免固定 500 ms 的发包周期恰好锁定在约 100 ms 的接收节拍上。P95 用升序样本第 `ceil(0.95 × n)` 个值，延迟统计只用有效收包。
- 仓库归档了 [25 份原始 CSV](lora-bench-2026-11-27/)，共 1,099 条数据行。文件按原名原样保存，写入错误列均为空。测试入口见 [lora_bench.py](../deploy/three-link/lora_bench.py)。

## 换口复测与断电定位

恢复无线接线，用已经做过回环的 COM22 接收，另一只转接板为 COM23。20 字节、2 Hz、随机间隔，完整帧数据如下。

| --- | --- | ---: | ---: | ---: |
| `20261127-162151-405010_COM23-COM22.csv` | COM23 → COM22，读取超时 50 ms | 40 / 40 | 141.04 | 190.00 |

- **换接收口后仍复现。** COM22 在 50 ms 与 13 ms 两种读取超时下的拟合周期都是 **100.19 ms**，首字节偏离拟合网格的 P95 分别为 **0.515 ms** 和 **0.570 ms**。反向测得约 **100.03 ms**。13 ms 对照缺序号 19，写入没有报错。原 COM17 的 USB 路径和应用默认 50 ms 读取超时都无法单独解释这个现象。
- **第一次重插留有歧义。** COM22 重插前后，两方向的接收节拍仍存在。前后测量间隔达到数分钟，观察到的相位变化可能混有时钟漂移。于是改为连续轮换方向采样，缩短重插前后间隔。
- **连续采样按实际重插分析。** `20261127-163231_COM22-power-cycle.csv` 的文件名记录了原计划。Windows 当时实际记录到 **COM23 重新枚举，COM22 一直在线**。CSV 共有 291 条收包记录，`stage` 都写为 `before`。以 COM23 作为接收端筛选，重插前后两段分别为 **135** 和 **12** 条，两段相邻接收时间相隔 **17.836454 s**。取重插前最后 30 个首字节时刻拟合约 99.935 ms 的网格，重插后首个落点相对旧网格的最短偏移为 **47.55 ms**。连续采样期间，以 COM22 为接收端有 144 条记录，未见同样紧邻的相位突变。与后续独立测量相比，另一方向的前后间隔更长，不能给出同等置信度的对照。

## 结论与仍待验证的环节

持续存在的约 100 ms 接收节拍，与 USB 重插时接收端节拍相位发生偏移，都指向接收模块的处理或 UART 输出调度。一个能解释现象的机制是包到达后等待下一个处理或输出时机，等待上限接近一个节拍。现场测试同时给 LoRa 和转接板断电，真正的内部等待点仍未分离。没有逻辑分析仪波形或固件计时，暂时无法把组包、空口、接收处理和模块 UART 输出各自的时间定量拆开，也不能断定所有 HD-M805 都有相同特性。

按这对模块当前的接法与参数，20 字节的无线完整帧耗时存在上百毫秒的波动，尚未证明它能满足实时遥控。比较新模块时可继续使用同机双串口、相同帧长和带抖动的发包方式，重点比较有效收包数、P95 与最长连续没有新指令的时间。若拿到逻辑分析仪，下一步同时测发射模块 RXD 和接收模块 TXD，直接观察节拍最早出现在哪个测点。

复测无线对照示例，串口号按本机枚举替换。

```powershell
cd deploy/three-link
python .\lora_bench.py --tx COM23 --rx COM22 --baud 9600 --hz 2 --count 40 --frame-bytes 20 --jitter 0.25 --no-pause
```

回环轮次用同一个串口对象调用测试程序的 `measure(port, port, ...)`。命令行的双串口模式要求两个不同的端口。
